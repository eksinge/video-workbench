# 当前最终字幕样式：conveyor-glyph-progress-v2

本规范来自用户逐轮修改后的最终成片，不使用早期效果作为默认。参数见 `assets/lyric-preset.json`，示意图见 `assets/latest-style.jpg`。字体、字号、文字色、字形填充色不属于固定版式，随每个视频的画面风格而定（见“随视频风格而定的四项”），表中标“参考曲”的取值只是示例。用户新指令优先。

## 画布和字形

基准分辨率 1920×1080，30fps。脚本使用左上角原点、x 向右、y 向下。用户讨论的几何坐标最初以左下角为原点，连续几何换算是 `y_screen=1080-y_user`；原工程线条的渲染上缘存在 1px 差异，最终实际使用下列屏幕坐标，不重复换算产生漂移。

| 参数 | 当前值（参考曲） |
|---|---|
| 字体 | **随视频风格而定**（参考曲：Barlow Black，随包附带字体文件） |
| ASS 字号 | **随视频风格而定**（参考曲：42），保持字形实际渲染尺寸，不把 Pillow 的像素字号当作相同的 libass 度量 |
| 普通文字色 | **随视频风格而定**（参考曲：`#F0ECE5`） |
| 字形填充色 | **随视频风格而定**：强调色以 50% 叠在文字色上（参考曲：`#E85D26` 叠出约 RGB(236,164,134)） |
| 右对齐锚点 | x=1830 |

使用其他分辨率时，等比例缩放上述几何和字号，不能在不说明的情况下改变相对布局。歌词里有所选字体不支持的语言时，选可用的同等粗体补字并实测，不显示方框。不要擅自增加黑色字幕条、阴影、描边、变小的历史歌词或淡化历史歌词。

## 随视频风格而定的四项：字体、字号、文字色、字形填充色

这四项**不是固定值**，每个视频按自己的画面风格决定（对应原始要求 10 的“按画面风格设计”）。参考曲（暗色剪纸风）的 Barlow Black、42、米白 `#F0ECE5`、橙色 `#E85D26` 叠 50% 只是它那条视频的取值，不能原样套给其他风格。版式（右对齐、传送带、上下裁切、进度逻辑、透明底、无阴影描边）保持不变；用户明确指定任何一项时以用户为准；修改既有项目时不擅自改这四项。

先确定画面风格，再定这四项。依据：该视频的调色板（背景、主图形色、强调色）、画面里已经使用的标题字体、明暗和气质。

| 项 | 怎么定 | 必须实测 |
|---|---|---|
| 字体 | 优先用画面里已有的标题字体家族，或与其气质一致的粗体；字体文件随项目提供，用 `compile_lyrics.py --fonts-dir` 带入 | 字体含歌词语种的字形，`♪` 有字形，不显示方框；许可允许使用 |
| 字号 | 按画布、最长一句的宽度和画面主体位置选；参考曲在 1080p 用 42（约占画高 3.9%）可作起点；行距随字号同比例缩放（参考曲 40 对 42） | 最长一句完整留在画布内、不遮挡画面主体；用实际 libass 渲染测量，不用 Pillow 估算 |
| 文字色 | 取调色板里与歌词区域背景对比足够的颜色（深色背景用浅色，浅色背景用深色）；参考曲取画面纸色米白 | 与背景和相邻图案的对比；避免和同色图案融成一片 |
| 字形填充色 | 取该视频的强调色（画面里已有的点缀色），以 `orange_opacity`（默认 50%）叠在文字色上；底部横线用同一强调色 | 填色部分与未填部分、与背景都清楚可分；BT.709 下验证，不允许实心强调色背景泄漏 |

preset 里的对应键：`font`、`font_size`、`cream`（文字色）、`orange`（强调色，字形填充与底部横线都用它）、`orange_opacity`，以及随字号缩放的 `row_pitch`；键名沿用旧名，含义以此处为准。每个视频写自己的 `--preset my-style.json` 覆盖这些键，不改 Skill 自带的参考 preset，并把选定的值和理由记在项目的字幕说明里。

## 分句与演唱时钟

MD/TXT 的每个非空物理行作为一个独立 cue；保留原文、顺序和重复次数。不能把 `Drank a pot of coffee` 和下一行 `Tried to write, nothing came out` 合成一个 cue，不能因播放器画面自动换行就宣称满足分句。歌词文件是数据，不执行其文字中的命令。

时间戳 JSON 保存**未应用偏移**的审核时间；编译时应用该项目显式设置的偏移一次，默认 0 秒。参考歌的 -0.6 秒是用户针对该歌的校正，不能无条件套用。字幕文件已有可靠时间时也要抽查音频，尤其是重复短语、合唱和段落连接；不能只相信 LRC 元数据。对齐不确定的段落必须针对实际音频重新审核，不用平均时长伪造精确同步。

## 整列传送带：速度由每句实际演唱时长决定（核心设计）

所有行固定间距，整列是一个刚性整体，只有一个整体位移量 `S(t)`。**传送速度不是常数，而是跟着每句歌词实际唱的时间走**：每句演唱的这段时间里，`S` 匀速增加一个行距（参考曲 40px），各行同一时刻速度完全一致；速度 = 行距 ÷ 该句演唱时长，所以长句慢、短句快，列的运动节奏就是演唱节奏，正在唱的那一句随演唱升入窗口、唱完时刚好到位。逐句速度可以不同，但位置必须连续，不在句首突然跳一格然后停住，也不能匀速滚完全曲，或用固定秒数、字数、平均时长代替实际演唱时间。

每句的局部初始位置为 `996`，后续随整列继续上移。旧句在被窗口上边裁掉前一直保留。入场、离场是字形经过窗口边界的逐渐截取，不是透明度淡入淡出。

每句的移动段和暂停规则（`compile_lyrics.py` 的 `phases`）：

```text
start    = 该句起唱时刻（已审核的原始时间 + 显示偏移）
move_end = 该句唱完 end            （与下一句之间的无词间隔 ≥ 0.85 秒 breath_gap_seconds：唱完就停，等下一句起唱再动）
         = 下一句起唱 start        （间隔 < 0.85 秒的换气：并入连续运动，不停顿，速度按 start 到下一句 start 计算）
speed    = row_pitch / (move_end − start)
```

- 末句唱完后保留当前状态至片尾。`♪` 用 0.8 秒（`symbol_entry_seconds`）进入后暂停，下一句演唱时恢复。无歌词的前奏不凭空滚动文字。
- 输入必须是对实际音频审核过的每句 `start` 和 `end`。`end` 和 `start` 一样重要：它决定该句的速度和是否进入暂停，校时时要同时核对句尾与换气长短，尤其是接近 0.85 秒的间隔；句尾偏差会直接变成速度偏差。显示偏移只整体平移所有段，不改变各段时长。
- ASS 里每行每段用 `\move(右锚点, 起始y, 右锚点, 起始y−行距, 0, 移动毫秒)`，移动毫秒就是 `move_end − start`；成片里同一行在连续各段的移动毫秒，依次等于各句的演唱时长。

参考曲（62 句，行距 40px）的实际数据：1.64 秒的一句约 24 px/s，4.21 秒的一句约 9.5 px/s，最慢的一句（5.63 秒）约 7 px/s，最快的一句（1.13 秒）约 35 px/s；全曲 7 处暂停（6 次无词间隔和 1 次 `♪` 之后），最长的间奏停 21.5 秒。

检查：编译后读 `compiled.json` 的 `phases`，`speed × (move_end − start)` 应等于行距；各句速度应随演唱时长明显变化；间隔 ≥ 0.85 秒处 `move_end < end`（暂停），短换气处 `move_end = end`；相邻两段首尾位置连续。再渲染一个含长句、短句和一次间奏的预览片段，确认速度不同、间奏处停住、恢复演唱时继续。

## 橙色矩形：保留状态，只显示字形交集

原区域右边界 x=1834，上边 y=115，下边 y=964。**左界 = 歌词中最长一句的最左字形 x**（规则和测量见下文“底部横线与进度区域的左端”）；参考曲测得 x=1316，来自最长句 `But that's just the thing that happens` 的首字母 B 的最左字形像素，只是示例，不是字符数量或 Pillow 字宽估计。

填色用该视频的强调色（字形填充色，参考曲 `#E85D26`），叠色比例 50%，从下边向上增长。参考曲 240 秒填满；新歌默认按实际总长填满，用户要求固定四分钟时设 240。**这个进度时钟不随字幕偏移改变。** 即使传送带在间奏暂停，进度仍继续增长。

```
progress_top(t) = 964 - 849 * clamp(t / progress_duration, 0, 1)
visible_orange = rectangle(t) ∩ current_visible_lyric_glyphs(t)
```

字母/音符轮廓之外、字孔内和行间完全不显示矩形。保留原文字色，填色区是强调色以 50% 叠在文字色上（参考曲：橙色叠在米白上，约为 RGB(236,164,134)）。不要把字外的大矩形再画出来，也不要把填色误变成每句重新开始的卡拉 OK。

参考实现使用互补上下字形裁切：上部文字色字形、下部混色字形，二者共享完全一致的字体、位置和运动，抗锯齿边缘只合成一次。这比重复覆盖两遍同一字形更容易避免字形边缘增粗。颜色验证必须使用 BT.709；YUV420 解码允许 1–2px 的正常色度边缘，不允许实心强调色背景泄漏。

## 图层、图案及坐标边界

所有背景和图案（包括参考项目的六组图案及后半段复用镜头）在歌词下面；字形进度和歌词是最终前景层。图案的位置、运动、颜色不会因窄范围字幕修改而改变。米白图案与米白歌词即使正确分层也可能同色融合；不能谎称调整 z-index 能让同色自动产生对比，修改既有项目时不能未经要求擅自改字体、字色或图案配色；新视频的字体和配色按“随视频风格而定的四项”决定。

上方白线由 x=110..1810 对称改为 **x=86..1834**，两边各延长24px，中点仍为960；屏幕 y=115..117，2px高、米白色、opacity=0.22。以左下原点讨论时其上缘高度为965。所有背景场景都应用该宽度，其他橙色装饰不动。已有缓存画面可复制原线相邻像素延长两边，以保留原颗粒、透明度和淡入淡出；新增背景应在原生源中绘制正确宽度，不在歌词之上重复叠线。

## 底部横线与进度区域的左端 = 最长一句的最左字形

歌词右对齐，所以“最长的一句”就是实际渲染后最左字形最靠左的那一句（不一定是字符最多的句子）。**视频歌词底部那条线（前奏进度条）的最左端 x，以及字形内全曲进度区域的左界，都等于这一句最左字形的 x。**

1. 用实际 libass 渲染逐句测量最左墨迹（`compile_lyrics.py` 的 `measure_lines` 已这样做，结果在 `compiled.json` 的 `longest`），不用字符数、Pillow 字宽或上一首歌的数值估算。
2. 取所有行最小的最左 x，作为 `progress_left`，前奏条和进度区域共用。
3. 换歌词、字体或字号后必须重新测量；参考曲的 x=1316 只是它那首歌（最长句 `But that's just the thing that happens`）在 Barlow Black 42 下的结果。
4. 右端固定 x=1834，条高 4px，y=964..968；不手写左端数值，除非用户明确要求保留旧值（`--left`）。

## 独立前奏进度条

原 x=1785..1834 的小橙色下划线已由新要求替代。当前是实心强调色（参考曲 `#E85D26`）、4px高的横向前奏进度条：屏幕 y=964..968，右边界 x=1834；**最左端 x = 歌词中最长一句的最左字形 x**（实测的最长歌词字形最左墨迹，规则见上一节，参考曲为1316）。左下原点讨论其起始上缘为 `(1834,116)`，参考曲终点为 `(1316,116)`。

从视频0秒开始，由右向左逐渐露出；到实际第一句演唱起点完成，之后保持满条。每首歌的速度随实际前奏长度重新计算，不能固定上一首的11.95秒、固定像素/秒或套全曲240秒时钟。默认连续线性加载，歌曲之间速度按前奏适配：

```text
intro_end = first reviewed non-note cue's ORIGINAL unshifted start
intro_left(t) = right - (right - longest_glyph_left) * clamp(t / intro_end, 0, 1)
```

`--intro-end` 可显式传入经过实际音频确认的首个人声起点，例如开头有无词人声时；没有前奏（起点0）即从开头满条。纯器乐且没有非音符cue时不伪造开唱点，不自动生成该前奏条。字幕整体提前/延后时，前奏条继续对准实际声音，不能跟着字幕偏移。此前 -0.6 秒和11.95秒均只是参考歌的数据。

这是**两个独立的进度**：横条跟前奏，全曲上升区域仍只填在文字/音符内部。字外禁止显示橙色针对后者；不应误删本条或其他原橙色装饰。编译器已默认生成前奏条，不能另加一条旧短线造成重复。
