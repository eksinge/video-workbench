# 本对话的要求整理与继承关系

用户明确要求将本对话中能够用于“导入音频和字幕，按最新字幕风格制作 MV”的要求写入 Skill。以下是完整的相关需求记录，区分当前默认、按需操作和已被后续修改替代的参数。闲聊问题不伪装成制作要求。

## 工作台与项目

1. 使用开源视频项目，制作中文项目发布动画，后来制作约十秒 Codex 介绍视频。
2. 把视频制作与音乐 MV 的项目整合到电脑上，学习并保留官方 Skills；最终为 Remotion + HyperFrames + 统一 `video-workbench` 入口。
3. 本地安装、桌面入口、浏览器访问；Skill 是给 AI 的调用流程，网页自己不自动执行 Skill。
4. 当前项目可以继续定制开发；上游两个引擎仍保持各自来源，不声称上游为原创。

## 音频与画面

5. 曾按 2分10秒把完整 FLAC 分开，输出在原文件夹。此为一次指定裁切需求，不是新歌曲默认切点。
6. 为歌曲制作暗色摇滚抽象 MV：剪纸、颗粒、图形随音乐变化。
7. 补上后半段完整音频时，不改变原有风格和前半段画面；复用原有图形/镜头扩展全曲。
8. 后续所有窄范围字幕修改，保持其他画面、音轨与效果。
9. 六组图案全部在歌词下层，不漏掉片头/眼睛/人像/碎片/虫群/片尾组。正确分层不能自动区分同为米白的图形和文字，不擅自用描边或黑底改变用户样式。

## 字幕文件与时序

10. 字幕在右下角，按画面风格设计，阴影背景改成透明。
11. 按提供的 TXT，后来 MD 分句；**一个换行就是一句，每次当前演唱行单独一行，不能把相邻两句合成一条并自动换成两行**。
12. MD 大概率没有时间戳，AI 自己依实际音频审核；有用户提供的时间戳文件时参考它，不机械信任。
13. 每句按实际演唱顺序接续。后来的堆叠需求取代“唱完就消失”，不取代按 MD 独立分句。
14. 参考歌曲逐次要求提前 0.2 秒，最终累计提前 **0.6 秒**。用户后来明确更正：这仅是当前歌曲的校正，不作为通用要求；其他用户/歌曲默认 0 秒，依实际情况自行调整。

## 空间、滚动和字形内进度

15. 坐标以左下角为原点讨论过；早期橙条大约 (1785,116)..(1834,116)，早期上方白线右端 (1810,965)；两者均已由下方最新规则替代。实际渲染以当前规范给出的屏幕边界为准。
16. 曾在 x=1634..1834、y=116..965 范围加 50% 原橙色矩形；后来改为由下至上、四分钟填满的进度条。
17. 当前歌词不消失而依次上叠，新句从橙线处逐渐露出，旧句到白线处逐渐被裁掉。窗口经过人体的比喻是**空间裁切**，不是透明度渐隐。
18. 初版每句只用 0.42秒移动一行、随后停住，被后续“整段像传送带一直动，速度按每句演唱时间调整，间奏可以停，恢复唱时继续”替代。
19. 行距修改顺序 60 → 56 → 50 → **40像素**；只使用最后值。
20. 最长句是 `But that's just the thing that happens`，实际 B 最左字形 x=1316，故原进度区域左界从1634扩到1316；用户称作 y 轴时实际意图是水平 x。新歌词重新测量最长实际字形，不硬编码上一首歌的句子。
21. 最新要求：矩形只在歌词文字内部显示，`♪` 也算字形，字外不显示矩形；矩形存在方式、状态、进度和透明度不变。当前默认是**字形内进度填色**，不再是大橙色矩形背景。

## 版本管理与调用

22. 只保留最新、上一版、上上一版，共三个成片；新版本验证后删除更旧导出。用户明确要求以后记住，保留原始素材和可编辑工程。
23. 调用名称 `$video-workbench`；提供音频与字幕后按本 Skill 制作，不要求用户重复叙述以上已固定的字幕样式。
24. 用户新指令可以覆盖任何默认参数。当前最终参数优先于历史尝试，不能把一首歌的切点、歌词数量或主题强制推广到所有视频任务。
