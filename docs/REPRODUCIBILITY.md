# 复现条件与验收

本仓库锁定的是字幕的排版和运动规范，画面内容随音乐变化。参考本机为 Windows、Node24.15、Remotion4.0.536、HyperFrames0.8.174、Python3.12、FFmpeg9.0.2（libass/libx264）、Barlow Black和Windows Segoe UI Symbol。

两个Node工程各自提交package-lock.json，安装使用npm ci。字幕脚本只依赖FFmpeg、Python/Pillow；ASR包另外安装，模型不嵌入仓库。模板用本地GSAP，不以网络字体或远程媒体作为成片运行依赖。

## 固定规范

`skills/video-workbench/assets/lyric-preset.json` 是唯一通用preset。默认字幕偏移0；项目可显式覆盖，不修改公共preset来照顾某一首歌。默认40px是锚点间距，不是上下两行可见墨迹之间的空白宽度；字形高度约30px，因此实际空白更小。

Barlow字体文件随仓库提供，实测字宽使用libass，不把Pillow point-size直接当作ASS字号。音符由Segoe UI Symbol补字。不同系统缺这款字体时需要确认替代字形；只有环境和字体一致，才能进一步谈逐像素一致。不要把安装成功说成输出已经匹配。

## 实测检查

`npm run test:style` 使用原创合成歌词/时间，验证默认0偏移、40px同速整列传送、字外透明、音符、上下裁切、间奏停/走与三版本清理。生成文件在忽略的examples/generated目录，不会动用户projects目录或真实成片。

公开参考图由Remotion的LyricBackgroundDemo背景与同一字幕编译器合成；测试文案不是某首发行歌曲的录音或歌词。它证明视觉实现，不代表对任意歌曲的ASR准确率。实际项目必须单独审核实际音频。

移植编译器时，原参考项目在12、30、60、80、120、170、200、240秒与之前已确认的字幕层比较，8个时刻像素完全一致。这一历史对比使用参考歌自己的-0.6秒项目偏移；通用preset随后按用户更正改为0，视觉参数保持不变。原录音与完整歌词不公开。

## 最低验收清单

- 与输入MD物理非空行数、原文、顺序和重复次数完全对应。
- 原始审核时间与显示偏移分开记录，声音完整，演唱起点经过实际音频审核。
- 文字持续上移而非阶梯跳动；间奏暂停，音乐进度继续增长。
- 40px锚点间距、字号42、透明底、无阴影/描边。
- 上白线/下橙线位置有半字入场与离场，字外无进度矩形。
- ♪存在并被橙色字形进度着色；在进度边界能看到一个字部分米白、部分橙色混色。
- 图案最后没有重新覆盖字幕；同色区域的对比问题不能误报为z-index已解决。
- 完整解码、时长/帧数/尺寸和音轨检查通过，再清理第四个更旧成片。
